## 0. 背景与现状

现有前端 `frontend/src` 已实现：左栏（文件 + 规则概述 chip + 选项）/ 右栏 Tabs（当前任务 / 历史任务），后台异步任务（轮询 + 任务存储），SSE 兼容。本次在既有骨架之上补齐并升级：

| # | 需求 | 现状 | 本次设计重点 |
|---|---|---|---|
| 1 | 审核规则可配置规则清单 | 仅有「可点击选择/取消」概述 | 升级为**独立「规则配置」管理页**（分类 + 规则 CRUD + 启用开关） |
| 2 | 一次上传多个并一并提交 | 已支持多文件上传 | 保持并强化「批量提交一个任务」语义 |
| 3 | 审核任务后台异步执行 | 已支持轮询 + task_id | 强化实时进度可视化与状态机 |
| 4 | 查看历史审核任务记录 | 已有历史列表 + 详情抽屉 | 详情中嵌入**逐条反馈**入口 |
| 5 | 每个审核项支持用户反馈（不认可需人工意见） | 无 | **新增「审核反馈」机制**：接受 / 不认可 + 人工审核意见 |
| 6 | 错别字类不认可结果进入系统，再次遇到相同错别字过滤提醒 | 无 | **新增「错别字忽略词库」**，由反馈自动沉淀 |
| 7 | 所有反馈统一汇集至反馈结果模块 | 无 | **新增「反馈结果」模块**，汇聚全量标注数据 |
| 8 | 反馈数据支持导出为模型调优训练数据格式 | 无 | **新增导出**，默认指令微调 JSONL，可切换格式 |

## 1. 信息架构与导航

将单工作台区升级为**四模块导航**（Antd5 `Layout > Sider` 可折叠侧栏 + 顶栏）：

```
┌─────────────────────────────────────────────────────────┐
│  顶栏：系统名 · 后端连通灯 · 当前用户 · 全局搜索          │
├──────────┬──────────────────────────────────────────────┤
│  导航     │  内容区（按选中模块切换）                     │
│  ● 工作台 │                                               │
│  ● 规则配置│   工作台：上传 / 选规则 / 提交 / 实时进度     │
│  ● 审核历史│   规则配置：规则清单管理 + 错别字忽略词库     │
│  ● 反馈结果│   审核历史：任务列表 + 详情(含逐条反馈)       │
│           │   反馈结果：全量反馈 + 训练数据导出           │
└──────────┴──────────────────────────────────────────────┘
```

- 工作台仍是主入口（上传→提交→看进度），历史/反馈为复盘与运营模块。
- 规则配置含两个 Tab：**审核规则**（CRUD）、**错别字忽略词库**（只读为主，可从反馈自动写入，也支持手动增删）。
- 审核历史的「详情」抽屉内对每条 AI 结论提供反馈；反馈一旦提交即同时写入「反馈结果」与（若是错别字且「不认可」）「错别字忽略词库」。

## 3. 页面详细设计

### 3.1 工作台（需求 2 / 3）
- **上传区**：`Upload.Dragger` 多文件（`multiple`），支持拖拽 + 点击，接受 `.pdf/.docx/.doc/.xlsx`；下方「已选文件」列表显示名称 / 大小 / 类型图标 / 删除（`Popconfirm` 二次确认）。
- **规则选择**：复用概述卡片，按类别分组的可点击 chip，支持「全选 / 清空 / 按类别切换」；默认选中上次使用的规则集（写入 `localStorage`）。
- **选项**：并行度、是否启用知识库一致性比对等开关。
- **提交**：「开始审核」→ 立即返回 `task_id`，界面**不阻塞**；右侧/下方切换为「当前任务」实时面板（进度条 + 滚动日志 `Spin` 占位「正在连接审核服务并解析文件…」）。
- **异步可视化**：状态机 `pending → running → success/failed/cancelled`；`Progress` 百分比 + `progress_message`；底部过程日志时间轴；结束显示汇总（合规率、问题计数、得分）。

### 3.2 规则配置（需求 1）
- 两 Tab：**审核规则** / **错别字忽略词库**。
- **审核规则**：`Table` 列 = 规则名称 / 类别（商务/技术/资质/格式/错别字…）/ 严重级别 / 启用开关 / 操作（编辑·删除）。顶部「新建规则」打开 `Modal`：名称、类别（Select）、级别（Select）、描述、启用。规则数据来自后端（现有已支持规则拉取），本页负责 CRUD。
- **错别字忽略词库**：`Table` 列 = 错词 / 建议正词 / 忽略次数 / 来源任务 / 最近忽略时间 / 操作（恢复提醒·删除）。该表由反馈（需求 6）自动写入，也支持手动维护。

### 3.3 审核历史（需求 4 / 5）
- `Table` 列 = 任务ID / 文件数 / 规则数 / 状态徽标 / 创建时间 / 结束时间 / 操作（查看详情·取消·删除）。
- 点击「查看详情」打开 `Drawer`（宽 `720px`）：顶部任务元信息 + 汇总；下方**逐条 AI 结论列表**（每条 = 文件 / 规则 / 级别 / AI 判定 / 理由 / 命中位置）。
- **每条结论即反馈单元（需求 5）**：
  - 状态徽标：`待反馈` / `已接受` / `已驳回`。
  - 操作：`接受`（一键认可 AI）/ `不认可`（展开「人工审核意见」文本域 + 提交）。
  - 提交后：该条标记为「已驳回（人工意见：…）」，并写入反馈结果模块；若为**错别字类且「不认可」**，同步写入忽略词库（需求 6）。

### 3.4 反馈结果（需求 7 / 8）
- `Table` 汇聚**全部用户反馈**：反馈ID / 任务ID / 文件 / 规则类别 / AI 原始判定 / 用户标注（接受·驳回）/ 人工意见 / 反馈类型（确认·驳回·错别字忽略）/ 时间。
- 筛选：按规则类别、反馈类型、时间范围；搜索框按文件/意见关键词。
- **导出（需求 8）**：按钮组「导出训练数据」，打开 `Modal`：
  - 格式选择：`指令微调 JSONL`（默认）/ `纠错对 JSONL` / `分类标注 JSON`。
  - 字段预览 + 行数统计；「下载」生成 `.jsonl`/`.json` 文件（Blob 前端导出，无需后端）。
  - 默认导出结构（指令微调）：
    ```json
    {"instruction":"请审核以下投标内容是否合规","input":"<原文片段>","output":"<人工标注结论/纠正后文本>","meta":{"task_id":"T-1024","rule":"错别字","ai_pred":"鑫智链→鑫智链(疑似错词)","user_label":"接受/驳回","opinion":"人工意见…"}}
    ```

## 4. 关键交互流程

### 4.1 异步任务执行（需求 3）
提交 → `POST /api/review/tasks` 立即返回 `task_id` → 前端 `useReviewTasks` 以 1.5s 轮询 `GET /api/review/tasks/{id}`，`running` 时显示进度与日志；`success/failed` 停止轮询并 Toast。支持「取消」(`POST .../cancel`) 与「删除」。

### 4.2 审核项反馈闭环（需求 5）
详情抽屉内逐条 → 选「不认可」→ 必填「人工审核意见」→ 提交 → ① 该条结论状态更新 ② `POST /api/feedback` 写入反馈表 ③ Toast「已记录反馈，将用于模型优化」。

### 4.3 错别字过滤机制（需求 6）
- 当某条结论 `rule_category == "错别字"` 且用户「不认可」时，将 `{wrong_word, suggestion, source_task}` 写入**忽略词库**。
- 后续任务执行前/中，引擎对 AI 产出的错别字提醒做匹配：若 `(wrong_word, suggestion)` 已在忽略词库，则**抑制该提醒**（不在结论中呈现，并标注「已按历史反馈过滤」）。
- 用户可在「规则配置 → 错别字忽略词库」中「恢复提醒」移除该条目。

### 4.4 反馈数据汇聚与训练导出（需求 7 / 8）
所有反馈（接受/驳回/错别字忽略）统一进入 `feedback` 表 → 「反馈结果」模块只读展示与筛选 → 一键导出为模型微调格式。导出字段含原始输入、人工标注输出、AI 预测与元信息，便于直接喂给监督微调/偏好对齐。

## 5. 组件状态与微交互参数（克制原则）

- 按钮：`hover` 亮度微调、`active` 缩放 `0.98`、`loading` 显示 `Spin`；主按钮 `type="primary"`。
- 卡片/抽屉进入：`opacity 0→1` + `translateY(4px)→0`，`0.2s` ease。
- 列表行：`hover` 背景 `#fafafa`，反馈提交后该行左侧出现 `2px` 主色高亮条。
- 仅动画 `transform` 与 `opacity`（GPU 加速），单页动效 ≤ 3 处，避免过载。
- 空态：`Empty` + 引导文案（如「暂无反馈数据，审核后在此查看标注沉淀」）。
- 加载：`Skeleton` 表格 / `Spin` 任务连接占位，杜绝空白屏。

## 6. 无障碍（WCAG 2.2 AA）清单

- 正文对比度 ≥ 4.5:1，大字号与 UI 组件 ≥ 3:1（上表色值均满足）。
- 语义化：`nav/ main/ aside/ table` 结构；侧栏 `<nav aria-label="主导航">`；表格 `scope` 与 `caption`。
- 键盘：侧栏/表格/弹窗均可 Tab 聚焦；`Drawer`/`Modal` 打开时焦点陷阱 + `Esc` 关闭 + 关闭后焦点归还触发元素。
- 焦点可见：统一 `:focus-visible` 主色描边 `2px`。
- 状态不仅靠颜色：级别/反馈状态均配**图标 + 文字**（如 ✔ 已接受 / ✕ 已驳回），避免色盲误读。
- ARIA：`Progress` 加 `aria-valuenow`；Toast/报错用 `role="alert"`；动态加载区 `aria-busy`。
